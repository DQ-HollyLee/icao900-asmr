## 一、我只想听 / 只想用字幕

> ⚠️ **音频不在这个仓库里。** 成品 mp3 是 **201 MB**，超过 GitHub 单文件 100 MB 的硬限制，
> 中间产物（逐句 clip、ffmpeg、缓存）加起来约 4.9 GB，更不可能入库。
> 仓库提供的是**完整配方**：给脚本一个 ElevenLabs Key，就能在本地复现出一模一样的音频（见第四节）。
> 字幕生成**不需要任何 Key**，只要有中英对照语料（见第五节）。

字幕文件放在 `subtitles/`：

| 文件 | 内容 |
|---|---|
| `ICAO900_v13x12_bilingual.srt` | **双语**：英文在上，中文在下（推荐） |
| `ICAO900_v13x12_en.srt` | 纯英文（适合自我测验：先看自己听懂没） |
| `ICAO900_v13x12_zh.srt` | 纯中文 |
| `ICAO900_v13x12_bilingual.vtt` | WebVTT 版，用于网页 `<track>` 播放器 |

全部是 **UTF-8 with BOM + CRLF** 编码——这是 Windows 播放器（PotPlayer / VLC / MPC-HC）和 Premiere Pro 识别中文最稳的组合，**不会乱码**。

**让播放器自动加载字幕**（最省事的做法）：

1. 把音频和字幕放在**同一个文件夹**；
2. 把字幕重命名成**和音频同名**（保留 `.srt` 后缀），例如
   `ICAO900_whisper_v13x12.mp3` ↔ `ICAO900_whisper_v13x12.srt`；
3. 用播放器打开音频即可。VLC、PotPlayer、mpv、MX Player 都支持同名外挂字幕自动加载。

## 二、在 Premiere Pro / 剪映里用

**Premiere Pro**

1. `文件 → 导入`（或直接把 `.srt` 拖进项目面板）；
2. 把音频素材拖到时间轴 `A1`；
3. 把字幕素材拖到视频轨道 **或** `字幕` 轨（新版 PR 会自动创建字幕轨道）；
4. 若出现中文乱码 → 说明拿到的是 ANSI 版本，请用记事本打开本仓库的字幕文件 →
   `文件 → 另存为` → 编码选 **UTF-8（带 BOM）** 覆盖（本仓库文件已经带 BOM，正常不会遇到）。

**剪映专业版**：`素材 → 字幕 → 导入字幕文件`，选 SRT 即可（同样依赖 UTF-8）。

## 四、想自己重新生成音频

**准备（一次即可）**

1. **Python 3.9+**（含标准库即可；做后处理建议装 `numpy`）
2. **ffmpeg**：本流水线只用它做滤镜链，放进 `.cache/ffmpeg.exe` 或加入 PATH
3. **ElevenLabs API Key**：注册后有免费额度。
   ⚠️ **千万别写进脚本**，用环境变量传（本仓库早期版本踩过这个坑）：

```bash
# Windows PowerShell
$env:ELEVENLABS_API_KEY = "sk_你的key"

# macOS / Linux
export ELEVENLABS_API_KEY=sk_你的key
```

**四步出成品**

```bash
cd icao900-asmr

# 1) 文本层：把原始语料清洗 + ICAO 发音规范化 → 01 / 02 / 03
python scripts/normalize.py

# 2) 先出 8 句样音试听（很重要：音色和气声好不好，8 句就听得出来）
python scripts/tts_generate.py sample

# 3) 全量 900 句（约 23 分钟，消耗约 3.1 万字符额度；Creator 套餐 13.1 万/月，够跑 4 次）
python scripts/tts_generate.py all --clips clips_v13x12 --name whisper_v13x12

# 4) 质检 + 整合 + 双声道 ASMR 后处理
python scripts/tts_generate.py check --clips clips_v13x12
python scripts/tts_generate.py post --clips clips_v13x12 --name whisper_v13x12 \
       --xfade 0.12 --pan-balance 0.90 --pan-dip 0.20 --pan-swap 2.5 --pieces 8
```

产物：`audio/ICAO900_whisper_v13x12.mp3` + `05_timestamps_whisper_v13x12.txt`。

**改参数不用重新合成、不花额度**（这是这套流水线刻意的设计）：

| 想改什么 | 怎么改 |
|---|---|
| 语速 | `--tempo`（默认 1.15） |
| 分块过渡的柔和度 | `--xfade`（默认 0.12 s） |
| 左右声道的差别有多大 | `--pan-balance`（0.90 = 90:10 ≈ ±19.1 dB） |
| 换边有多快 | `--pan-swap`（默认 2.5 s） |
| 换边时音量下压多少 | `--pan-dip`（默认 0.20，见第六节） |

## 五、只想改字幕

`make_subtitles.py` 把「中英对照原文」配「成品时间戳」对齐成字幕，**自带对齐校验**：

```bash
python scripts/make_subtitles.py \
       --cn "中英对照.txt" \
       --ts "05_timestamps_whisper_v13x12.txt" \
       --out subtitles
```

两种时间轴模式：

- `--mode gap`（默认）字幕在本句说完后再留 0.2 s 就消失，句间 2.3 s 静音**不显示文字**——视觉节奏跟着呼吸走，适合睡前；
- `--mode continuous` 字幕一直显示到下一句开始，适合跟读。

它会自动做四件事并在终端汇报：序号连续性检查、**串行检测**（把中英 shift 一句看是否更匹配）、缺译检查、句幕数量比对。

> 这套校验不是摆设：解析第一版中英对照文件时，第 99 句的中文翻译是「118.3 校波。」——
> 它以 `118.` 开头，被误当成第 118 句，导致后面全部串行。现在的解析器按**序号连续性**驱动，并把「不含中文的行」并入上一句英文（原文件里长句会折行），才得到干净的 900 句。

## 六、技术看点

完整推导、实测数据与已经核验的文献都写在 **`docs/TASK_ARCHIVE.md`**，这里只列三条最反直觉的：

**1. 轻声 ≠ 气声，频谱走向是相反的。**
"把音量关小"得到的是轻声；气声是靠气流摩擦——实测真人录音（同一句正常 vs 气声）：
谐噪比 +1.8 → −4.3 dB，谱质心 581 → 2052 Hz，能量从 **<300 Hz 搬到了 >2 kHz**。
所以早期"压低中高频 + 降响度"的做法全部走反了方向——那几个被压掉的频段正是气声所在。

**2. ElevenLabs 的 `[whispers]` 标签，走向和真人气声相反。**
相对无标签版，它在 100~200 Hz **+7~13 dB**、2 kHz 以上 **−7 dB**，靠"压低变厚"实现低语——听感是**成熟、偏远**。
它仍然是唯一显著生效的标签（高频占比 1.7% → 6.5%），但要接近真人气声，得理解这个偏差。

**3. 声道切换穿越正中间时，要把总音量临时下压 20%。**
同一个声音给两只耳朵听，比只给一只耳朵听更响（双耳响度求和）。等功率声像法则只配平了**能量**，配不平**听感**。
四条已核验的心理声学实测给出求和量 4.6~6.5 dB，扣掉等功率法则本来就该降的 3 dB，净剩 **1.6~3.5 dB**。
本项目按下压 20%（−1.94 dB）实现，落在区间偏保守一端；A/B 差分实测：单侧停留 **+0.08 dB**（等于不动），穿越中心 **−1.87 dB**。

另外还有：`atempo` 绝对不能分段跑（内部窗口对齐 4096/2048 采样，每接缝错位 40~85 ms）、
`-ss` 不能直接落在 mp3 上、`os.remove` 调几十次会被安全删除守卫拦截——详见 `PROJECT.md` 的踩坑表。
